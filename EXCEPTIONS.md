# EXCEPTIONS.md

Deviations from `Engineering Standards.html`, with owner sign-off and an expiry date.

| # | Rule | Deviation | Why | Approved by | Date | Expires |
|---|---|---|---|---|---|---|
| 1 | §1 Mandated stack: DB is MSSQL | Local development keeps SQL Server (matches the standard). **Deployed: Firestore** (decided 2026-10-23), not MSSQL. `src/repos/` gets a second, Firestore implementation behind the same interface; `npm test` runs the full suite against SQL Server and the Firestore emulator. Rules SQL Server enforces today (unique emails, at least one active superadmin, links, immutable map versions) are enforced and tested in code. During the internal test the server runs on a PC behind Cloudflare Tunnel and files stay on its disk (Firebase Storage needs the Blaze plan). See `docs/shopper-hybrid-decisions.md` §4. | Lowest running cost for the pilot (free allowance, pay per use) and one Firebase project for hosting, storage and data; the owner accepted the larger rewrite and two data layers. | dev4@dynamiqes.com (project owner) | 2026-10-21; Firestore chosen 2026-10-23 | Review 2027-01-21 |
| 2 | §1 / §4 Frontend is Flutter Web | three.js (JavaScript) embedded in an HTML element inside the Flutter map editor page, used solely for the 3D map preview. No other UI code outside Flutter. Built in Round 17: three.js 0.186.1 (MIT) bundled in `LIQo web/web/map3d/`, loaded from the app itself. | A real 3D preview beside the 2D editor is a required deliverable (US-036). Flutter has no mature 3D scene engine for the web; three.js reads the same map JSON the editor produces. Decided by the product owner on 2026-10-21. | dev4@dynamiqes.com (project owner) | 2026-10-21 | Review 2027-01-21 |
| 3 | §1 / §4 Frontend is Flutter Web | Small JavaScript helpers bundled in `LIQo web/web/` (no UI): pdf.js 5.7.284 (Apache-2.0) turns a PDF page into a picture (Round 15); `plan_convert/convert.js` with UTIF.js + pako (MIT) and libheif-js 1.23.2 (LGPL-3.0, unmodified, licence texts beside it) turn TIFF/HEIC plans into PNG (Round 16). All served from the app itself; nothing loads from outside. | Flutter Web cannot decode PDF, TIFF or HEIC; plan upload in these formats was requested by the owner. | dev4@dynamiqes.com (project owner), plan approvals | 2026-10-22 | Review 2027-01-22 |
| 4 | Deployment platform (see #1) | DWG plans need **ODA File Converter** (Open Design Alliance, free, its own licence accepted by the owner) installed beside the API. On Linux it needs a virtual display (`xvfb-run`). Firebase Hosting cannot run it; for the internal test the API runs on a Windows PC (2026-10-23), where the converter is installed beside it (`ODA_FILE_CONVERTER`). A container host (Cloud Run) would need it in the image. Without it, DWG uploads are refused with a clear message; everything else works. | DWG is AutoCAD's closed format; the owner chose ODA File Converter (2026-10-22). | dev4@dynamiqes.com (project owner), plan approval | 2026-10-22 | Revisit before a cloud host |
